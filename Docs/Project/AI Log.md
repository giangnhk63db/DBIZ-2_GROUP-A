# AI log: where AI suggested something wrong

Kept for the whole project. One entry each time an AI tool proposed something the team did not
accept, with the decision and where it was recorded. (UC = use case; ID = identifier.)

| # | Lesson | What AI suggested | Why it was wrong for the Market Price use case diagram | What the team did |
|---|---|---|---|---|
| 1 | L? (use case diagram) | Model the relationship between UC-2.10 (Backfill 12-Week Price History) and UC-2.06 (Sync 180-Day Listing History) as an `<<include>>`, implying the 180-day listing synchronization runs in every backfill run | UC-2.06 is required only when a newly added vehicle belongs to a car model that does not yet exist in the listing repository. When the model already exists, the backfill retrieves the stored listings directly and UC-2.06 is not executed. Since UC-2.06 is triggered conditionally and UC-2.10 can be completed without it, the relationship is optional and should be an `<<extend>>` | Revised to UC-2.06 `<<extend>>` UC-2.10, with the arrow directed from UC-2.06 to UC-2.10. Added the extension condition "for the 1st signed up car model" to the relationship so the trigger is explicit in the diagram. Cross-checked against the UC-2.10 specification, which states the 180-day synchronization is performed beforehand only if the car model is absent from the repository |
| 2 | L? (sequence diagram) | Generate Mermaid code for the sequence diagrams from the provided use case list, but the output paraphrased or shortened several use case names instead of keeping the original ones | The use case names were not yet consistent across the different diagrams when the sequence diagrams were generated, and there was no fixed list of names for the AI to follow, so it wrote its own shorter or reworded versions. The names in the sequence diagrams therefore did not match the original use case list | Verified each sequence diagram against its use case ID rather than by name alone, and compared it with the original use case list. Corrected every title or message that deviated from the official name manually in the Mermaid code. Every sequence diagram now carries the exact use case ID and name defined in the original list |
| 3 | L? (screen spec numbering) | Number the Upload invoice sheet by continuing the main screen sequence (19 to 48), and give the red error block in the Error validate FE (2) state two numbers (title and explanation line) | The Upload invoice sheet belongs to S-F01-04 but is drawn as its own set of mockup frames (S-F01-04-modal-*), so the team numbers it as its own sequence. The team had also agreed that one visual block at one position gets one number. Continuing the sequence and splitting the text made the numbered images disagree with the element inventory | Kept two separate sequences in the same screen spec (1 to 19 for the main screen, 1 to 41 for the sheet). Gave the whole red text one number, Status message (5), and listed its content state by state in the element inventory |
| 4 | L? (screen spec states) | Keep generic state names such as "Error" and "Manual verification" in the States tables | The mockup frames are named by error type (Error-API, Error-validate-FE, Error-validate-BE). With generic names, a reader cannot tell which mockup image belongs to which state | Renamed every state after its mockup frame, and updated every interaction and rule that referred to the old state names |
| 5 | L? (screen spec inventory) | Include non-existent UI elements in S-F01-02 and S-F01-03 element inventories (such as "Năm sản xuất" instead of "Màu sơn" and an inline 12-week price chart on S-F01-02, and a "Tải thêm lịch sử" pagination button plus a "Chưa xác minh km" badge in the Empty state of S-F01-03) | The exported 360px mockup frames (S-F01-02-\*.png and S-F01-03-\*.png) display "Màu sơn" ("Trắng"), show only the latest weekly reference price ("850.000.000 đ") on S-F01-02, render all VETC toll records without a load-more button on S-F01-03, and display a #FFF3DC warning banner instead of a badge in the Empty state. Keeping AI's inferred elements made the element inventory disagree with the numbered mockup images | Audited every row of the element inventories against the actual mockup frames, replaced "Năm sản xuất" with "Màu sơn", removed "Tải thêm lịch sử" and the inline chart from the base inventories, and logged missing specification fields under Open questions in screen-spec-S-F01-02.md and screen-spec-S-F01-03.md |
| 6 | L? (screen spec terminology) | Use "Quãng đường tối thiểu" as the section card header in screen-spec-S-F01-02.md and screen-spec-S-F01-03.md, and list transient state banners and popups only as an unnumbered footnote below the element inventory table | All five mockup frames for both S-F01-02 and S-F01-03 use "Số km đã đi" as the visible section card header (with top bar "Lịch sử qua trạm VETC" on S-F01-03), and state-specific banners (Loading, Empty) and modals (Error, Success) appear as visible visual blocks that must be mapped by number in the element inventory | Updated the section card header names in screen-spec-S-F01-02.md and screen-spec-S-F01-03.md to "Số km đã đi" to match the mockups, and assigned explicit element numbers to state banners (33–36 in S-F01-02; 11–12 in S-F01-03) and modal elements (37–42 in S-F01-02; 13–18 in S-F01-03) while keeping the dimmed backdrop unnumbered |
